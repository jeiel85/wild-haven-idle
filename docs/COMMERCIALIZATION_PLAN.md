# COMMERCIALIZATION_PLAN.md

# Wild Haven Idle 상용화 개선 계획

이 문서는 v0.2.0 이후, 광고/결제/계정/네트워크 의존성을 추가하지 않는 범위에서
"첫 사용자 경험 → 다음 행동 명확화 → 장기 리텐션 기반"의 순서로 게임을 다듬기
위한 단계별 개선 계획을 정리한다. `AGENTS.md`의 정책 (특히 §8 금지/사전 승인,
§9 IP/윤리 규칙)을 위반하지 않으며, MVP의 로컬 우선 데이터 정책을 유지한다.

## 0. 원칙

- 광고 SDK, 결제 SDK, 분석 SDK, 로그인 SDK, 클라우드 DB SDK, 원격 설정 SDK,
  네트워크 권한, 알림 권한 추가 금지.
- 감정 압박형 표현, 다마고치/전자펫 연상 표현 금지.
- 사용자 데이터 구조 변경 시 기존 사용자 데이터를 보존한다 (마이그레이션 기본값
  설계).
- 한 번에 한 가지 개선만 반영하고, 매 단계마다 검증·문서·CHANGELOG를 함께
  갱신한다.

## 0.5 Phase 0.5 — Design Polish (병행 트랙)

목표: 절차적 Compose Canvas 위주의 현재 비주얼을 *졸업작품 톤*에서 벗어나
일관된 시각 정체성으로 끌어올린다. Phase 1~3 기능 작업과 병행해 진행한다.

전제: 모든 일러스트 에셋은 `docs/ART_DIRECTION.md` §8~§10의 *AI 생성 +
사람 검수* 파이프라인을 따른다. 한 번에 한 가지 AI 서비스만 쓰고, 도입한
모든 에셋은 `docs/ASSET_LICENSES.md` §2에 메타데이터를 기록한다.

| 우선 | 항목 | 설명 | 완료 기준 |
|---:|---|---|---|
| P1 | 비주얼 시스템 토큰화 | 컬러/타이포/spacing/라운딩을 Compose 테마로 토큰화 (현재는 머티리얼 기본값에 의존) | `WildHavenTheme`이 본 문서 §3 컬러를 반영, 카드/버튼/타이포가 토큰만으로 정의됨 |
| P2 | 보호구역 헤더 PNG 교체 | 현재 절차적 Canvas 헤더를 AI 생성 풀폭 일러스트 1장으로 교체 (보호구역 풍경) | `wh_habitat_forest_001.png` 추가, ASSET_LICENSES.md 기록, 헤더 시각 인상 향상 |
| P3 | 동물 5종 일러스트 1차 | 절차적 도형 → AI 생성 PNG 1차 5종 (rabbit/fox/deer/owl/lynx) | `wh_animal_*_001.png` 5종, ASSET_LICENSES.md 5건, AnimalIllustration이 PNG 사용 |
| P4 | 카드/버튼 마이크로 폴리시 | 그림자, 라운딩, spacing, 진행률 타이포 위계 정리 | 홈 화면 한 페이지 안에서 시각 위계가 명확히 읽힘 |
| P5 | 모션 정돈 | 회복 완료/탭 보상/오버레이 등 작은 모션의 timing curve 통일 | 동일 easing/duration 토큰 사용, 산만함 감소 |

P1은 코드만으로 가능 (AI 서비스 없이도 시작 가능). P2/P3는 AI 서비스 결정 후
에셋 1개 시범 생성 → 검수 → 도입 순으로, 한 번에 한 에셋씩 도입한다.

## 1. Phase 1 — 첫 5분의 마찰 제거

목표: 처음 앱을 켠 사용자가 "무엇을 해야 하는지"를 30초 안에 이해하고, 첫 의미
있는 행동(탭, 회복 지원, 보호구역 확장)을 자연스럽게 한 번 이상 수행하도록 한다.

| 우선 | 항목 | 설명 | 완료 기준 |
|---:|---|---|---|
| P1 | 첫 사용자 온보딩 오버레이 | 신규 데이터일 때만 1회 노출되는 3-step 환영/가이드 오버레이 | 신규 설치 → 오버레이 노출, "시작" 후 재실행해도 다시 뜨지 않음, 기존 사용자에게는 표시되지 않음 |
| P2 | 다음 행동 카드 강조 | 홈에서 "지금 할 수 있는 가장 가치 있는 행동"을 단일 카드로 명시 (이미 존재하는 다음 해금/회복/확장 중 추천) | 카드가 항상 한 가지를 명확히 추천하고, 비용/효과를 한 줄로 보여줌 |
| P3 | 보호 포인트/생산량 시각 가독성 정리 | 숫자 라벨, 단위, 다크 대비 점검 | 작은 화면(360dp)에서 잘림/오버플로 없음 |

## 2. Phase 2 — 짧은 세션의 보상감

목표: 30초~3분의 짧은 접속에서도 "성장한 느낌"을 더 분명하게 만든다.

| 우선 | 항목 | 설명 | 완료 기준 |
|---:|---|---|---|
| P1 | 일일 접속 보상 (로컬) | 하루 1회 접속 시 보호 포인트 보너스, 광고/결제 없음 | 자정 경계 기준으로 1일 1회 자동 지급, 마지막 수령 시각을 로컬에 저장 |
| P2 | 첫 회복 완료 축하 | 어떤 동물이든 회복 단계 5(안정) 도달 시 1회 축하 다이얼로그 | 동물별 1회만, 다시 켜도 재노출되지 않음 |
| P3 | 오프라인 보상 다이얼로그 개선 | 보상량과 함께 "다음에 무엇을 할 수 있는지" 안내 | 오프라인 보상 다이얼로그가 추천 행동 1줄 포함 |

## 3. Phase 3 — 장기 리텐션 기반

목표: 며칠~몇 주 단위로 다시 켜고 싶은 작은 목표를 만든다. (외부 SDK·서버 없이.)

| 우선 | 항목 | 설명 | 완료 기준 |
|---:|---|---|---|
| P1 | 일일 과제 (3개 / 로컬 롤링) | 탭 N회, 회복 지원 N회, 보호구역 1회 확장 등 가벼운 데일리 | 자정마다 갱신, 진행률 표시, 완료 시 보호 포인트 보상 |
| P2 | 도감 진척 알림 카드 | 발견/보호 진행률을 한눈에 보여주는 홈 카드 | 도감 화면 진입 없이 진척률 인지 가능 |
| P3 | 보호구역 마일스톤 보상 | 보호구역 Lv.5/10/20 등 도달 시 1회 보상 | 마일스톤 도달 시 1회 보상 후 표시 토글 |

## 4. 명시적 비목표 (이번 분기)

- 광고 SDK 통합
- 인앱 결제 / 상점 화면
- 로그인, 계정, 클라우드 동기화
- 푸시 알림 / 백그라운드 작업
- 분석 / 크래시 리포트 SDK
- 외부 기부/단체 연계

이 항목들은 별도 사전 승인이 있을 때만 검토한다 (`AGENTS.md` §8 참조).

## 5. 운영 규칙

- 한 작업 루프에서는 위 표의 한 항목만 선택해 구현한다.
- 데이터 모델을 확장할 때는 기본값과 마이그레이션 동작을 함께 정의한다 (기존
  사용자에게는 첫 노출용 보상/오버레이가 다시 뜨지 않도록 한다).
- 모든 변경은 `CHANGELOG.md`, `HISTORY.md`, `.agent/progress.md`,
  `.agent/tasks.md`에 반영한다.
- 검증은 최소 `./gradlew :app:compileDebugKotlin`과 `./gradlew :app:testDebugUnitTest`를
  통과해야 한다.

## 6. 현재 상태 (작성 시점)

- v0.2.0에서 홈 중심 통합과 다음 해금 진척률 카드가 들어가 "다음 행동의 방향"은
  부분적으로 보인다.
- v0.3.0에서 첫 사용자 온보딩 오버레이 (Phase 1 P1) 도입 완료.
- 일일 접속 보상, 일일 과제는 아직 없다.
- 비주얼은 절차적 Compose Canvas + 머티리얼 기본 토큰 — 일관된 시각 정체성 부재.
- 다음 작업 후보:
  - **Phase 0.5 P1 (비주얼 시스템 토큰화)** — AI 서비스 결정 없이도 즉시 시작 가능.
  - **Phase 1 P2 (단일 추천 다음 행동 카드)** — 기능 트랙.
  두 트랙은 서로 충돌하지 않으므로 사용자가 진행 순서를 선택한다.
